# Fusio project

This repository is a [Fusio](https://www.fusio-project.org/) project, a PHP (>= 8.4) API management platform used here as a
framework. The whole API is defined in files under `resources/` (metadata) and `src/` (PHP code) and then applied to the
Fusio instance with `php bin/fusio deploy`. The `todo` resource is the reference implementation: when in doubt, copy
its patterns.

Docs: https://docs.fusio-project.org/

## Folder structure

| Path | Purpose | Edit by hand? |
|------|---------|---------------|
| `.env` | `FUSIO_CONNECTION` (Doctrine DBAL URL, e.g. `pdo-mysql://user:pass@localhost/db`), `FUSIO_URL`, mailer, and so on | yes |
| `.fusio.yml` | Deploy manifest that `!include`s the `resources/*.yaml` files | rarely |
| `resources/config.yaml` | API info (title, description, contact, license) and mail templates | yes |
| `resources/operation.yaml` | Maps operation IDs to operation files: `"todo.getAll": !include resources/operations/todo/collection.php` | yes |
| `resources/operations/<entity>/*.php` | One operation (route) per file | yes |
| `resources/typeschema.json` | TypeSchema spec, the source of every DTO in `src/Model` | yes |
| `resources/event.yaml` | Domain events that consumers can subscribe to with webhooks | yes |
| `resources/cronjob.yaml` | Periodic jobs that point to an action class | yes |
| `resources/scope.yaml` | All scopes of the API | yes |
| `resources/role.yaml` | Scopes assigned to each role | yes |
| `resources/container.php` | Symfony DI config, with autowiring for Action, Service, Table, View | rarely |
| `src/Action/<Entity>/*.php` | Action classes, the entry point of an operation | yes |
| `src/Service/<Entity>.php` | Business logic for writes | yes |
| `src/View/<Entity>.php` | Read models that build JSON responses | yes |
| `src/Migrations/VersionXXX.php` | Doctrine migrations | yes, after generating |
| `src/Model/*` | DTOs | **no**, generated by `generate:model` |
| `src/Table/Generated/*` | Table, row, and column classes | **no**, generated by `generate:table` |
| `src/Table/<Entity>.php` | Extends the generated table, so you can add custom queries here | yes, created once by the generator |

## Commands

```
php bin/fusio generate:model                      # resources/typeschema.json -> src/Model
php bin/fusio migrations:generate --no-interaction  # new empty migration in src/Migrations
php bin/fusio migrations:migrate --no-interaction   # run migrations; ASK THE USER FIRST
php bin/fusio generate:table                      # DB tables with prefix app_ -> src/Table/Generated
php bin/fusio adduser                             # create an account (interactive; user runs it via `!`)
php bin/fusio login                               # authenticate the CLI (interactive; user runs it via `!`)
php bin/fusio whoami                              # current CLI user, `null` = not logged in
php bin/fusio deploy                              # push resources/* to the Fusio instance (needs login)
php bin/fusio generate:sdk client-typescript      # SDK zip in output/
php bin/fusio route                               # list routes
```

## Conventions

- **Never edit generated code** (`src/Model/*`, `src/Table/Generated/*`). Change `typeschema.json` or the migration
  instead, then regenerate.
- **App tables must use the `app_` prefix** (e.g. `app_todo`). `generate:table` ignores every other table, and the
  `fusio_*` tables belong to Fusio. Table `app_todo` becomes `TodoTable`, `TodoRow`, `TodoColumn` in
  `App\Table\Generated` plus `App\Table\Todo`. Inject `App\Table\Todo`, never the `Generated` class (the DI container
  excludes `Generated`).
- **Operation IDs** use `<entity>.<verb>`: `getAll`, `get`, `create`, `update`, `delete`. Operation files are named
  `collection.php`, `entity.php`, `create.php`, `update.php`, `delete.php`. Path params use `:id` (e.g. `/todo/:id`).
- **Every operation needs a scope** (`setScopes([...])`). The scope must exist in `scope.yaml` and be assigned in
  `role.yaml`. `setPublic(true)` means no auth is required (typical for GET). Writes are `setPublic(false)`.
- **Roles:** `Administrator` gets every scope. `Consumer` (the default role for new registrations) gets the scopes
  that app users need.
- **Read vs. write actions:** GET actions delegate to a **View** (`getCollection` / `getEntity`). Create, update, and
  delete actions delegate to a **Service** and return `App\Model\Message`. Actions stay thin, with no business logic.
- **Incoming payloads** reach the action already deserialized and validated as the DTO set with `setIncoming(...)`:
  `$request->getPayload()` returns e.g. `Model\Todo`. Path and query params come from `$request->get('id')`.
- **Errors:** throw `PSX\Http\Exception\*` (`BadRequestException`, `NotFoundException`, `ForbiddenException`, ...).
  Fusio maps them to HTTP status codes.
- **Current user:** `$context->getUser()->getId()`. Pass `ContextInterface` from the action to the service when needed.
- **Events:** services dispatch an event for every important state change through `Fusio\Engine\DispatcherInterface`
  (see `src/Service/Todo.php::dispatchEvent`). The dispatched name must match a key in `resources/event.yaml`
  **exactly**. Naming: `<entity>_<past-tense-verb>`, e.g. `todo_created`.
- **DI:** constructor injection only. Classes are `readonly` with promoted `private` properties. Anything under
  `src/Action`, `src/Service`, `src/Table`, `src/View` is autowired, so new folders need an entry in
  `resources/container.php`.
- **Code style:** PSR-4 `App\` namespace mapped to `src/`, a short class docblock on actions and services, and PHP 8.4
  syntax. Use `phpstan` (`vendor/bin/phpstan`) and `rector` for checks.
- After changing anything in `resources/`, remind the user to run (or offer to run) `php bin/fusio deploy`.
- **Deploy requires a logged-in CLI**, so the order is `adduser`, then `login`, then `deploy`. After a fresh install
  no user exists, so `adduser` (role 1 = Administrator) must come first. Check with `php bin/fusio whoami`. Never run
  `adduser` or `login` yourself or handle passwords. Ask the user to run them with the `!` prefix.

## Workflows (skills)

- `/fusio-setup`: first-time setup (DB credentials, config.yaml, install, admin user, first deploy)
- `/fusio-resource`: add a complete REST resource end to end (schema, migration, table, view, service, actions,
  operations, scope, events, deploy)
- `/fusio-migration`: change the database schema and regenerate table classes
- `/fusio-cronjob`: add a periodic job
- `/fusio-deploy`: apply `resources/*` to the instance
- `/fusio-sdk`: generate a client SDK
